KSZ8895MLUB-ND — Full Explainer

What this chip is, what it does, and what every term in its datasheet actually means — written assuming zero prior networking-hardware background.

1. The big picture: what problem does this chip solve?

Imagine you have several devices — a router's CPU, a Wi-Fi access point radio, a couple of Ethernet jacks on the back of a box — and you need them all to be able to talk to each other and to the outside world over Ethernet. You could use five separate single-port Ethernet chips and wire them together with glue logic, but that's expensive, uses more board space, and you'd have to build all the "which port does this packet go to" logic yourself.

The KSZ8895 is a single chip that is a 5-port Ethernet switch — the same functional block you'd find inside a cheap 5-port desktop switch you can buy for $10, except here it's one IC you solder onto your own board, with a few pins that let a host microcontroller peek inside and reconfigure it, or none at all if you just want it to behave like a plain unmanaged switch out of the box.

Analogy: Think of it as a tiny automated mail-sorting room. Five doors (ports) each connect to a different building (device). A letter (packet) comes in one door; the sorting room reads the address on the envelope and, without a human involved, slides it out the correct door to reach its destination — and if it doesn't yet know which door leads to that address, it briefly shouts the letter out every door and remembers whichever door the reply came back through, for next time. That memory is the "MAC address table," and the automatic address-learning is the core job of every Ethernet switch, including this one.

2. What's physically inside the chip

Reading the diagram: each of the five external ports has its own MAC and its own PHY, and all five feed into one shared switch fabric with one shared memory pool. A host CPU is optional — it talks to the chip over SPI, I²C, or MDIO if present, purely to read status or change configuration; it does not sit in the data path. If there's no CPU, an EEPROM (or just the chip's built-in defaults plus pin-strapping) configures it once at power-up and then it runs completely autonomously.

3. Managed vs. unmanaged — the chip's two personalities

ModeWhat it meansWhen you'd use it
UnmanagedNo CPU talks to the switch at runtime. Behavior comes from internal defaults, optionally overridden by an EEPROM read once at boot, or by resistors on strap pins.Simple "just be a 5-port switch" designs — e.g. adding extra Ethernet ports to a device with no spare CPU cycles to manage a switch chip.
ManagedA host CPU has live register access over SPI or MDC/MDIO and can read statistics, change VLANs, adjust QoS, monitor link status, and reconfigure anything at runtime.Routers/gateways where you want VLAN segmentation, QoS prioritization for VoIP, port mirroring for diagnostics, or dynamic control.

4. Full terminology glossary

Layer 2 / Ethernet basics

TermPlain-English meaning
MAC (Media Access Controller)The digital logic block that handles Ethernet framing — building/parsing packet headers, timing (inter-packet gaps), collision handling, and flow control. It speaks a standardized digital interface (MII/RMII) on one side and hands finished frames to the switch fabric on the other. Not to be confused with "MAC address" (see below) — same acronym, different but related concept.
MAC addressA 48-bit hardware address burned into (or configured on) every Ethernet device, used to identify who a packet is from and who it's going to at Layer 2. The switch's whole job is learning which port each MAC address lives behind.
PHY (Physical layer transceiver)The analog front-end that actually drives and receives the electrical signal on the copper cable — line drivers, equalizers, clock recovery, the works. It converts between the MAC's digital bits and the real analog waveform on the wire.
Layer 2 / Layer 2 managed switch"Layer 2" refers to the OSI networking model's data-link layer — the layer that deals with MAC addresses and physical framing, as opposed to Layer 3 (IP routing) or Layer 4 (TCP/UDP ports). A "Layer 2 managed switch" makes forwarding decisions based on MAC addresses, and exposes configuration/monitoring to a manager (CPU).
10BASE-T / 100BASE-TXIEEE standard names for 10 Mbps and 100 Mbps Ethernet over twisted-pair copper cable. "100BASE-FX" (mentioned for one variant of this chip family) is the same speed but over fiber optic cable instead of copper.
Full duplex / half duplexFull duplex = can send and receive simultaneously (like a phone call). Half duplex = only one direction at a time (like a walkie-talkie) — a legacy mode, relevant mainly for old hubs or forced-speed links.
Store-and-forwardThe switch's forwarding strategy: it fully receives an entire frame into its internal buffer, checks it for errors, and only then transmits it out the destination port — as opposed to "cut-through" switching which starts forwarding before the frame is fully received. Store-and-forward is slightly higher latency but never forwards a corrupted frame.
Non-blocking switch fabricMeans the internal path connecting any port to any other port has enough bandwidth that traffic on one port pair doesn't have to wait for or steal bandwidth from a different port pair — all ports can be busy simultaneously without starving each other.

Wiring / signaling terms

TermPlain-English meaning
MDI / MDI-XTwo wiring conventions for which pins on an RJ45 jack are "transmit" vs "receive." A network card is normally MDI; a hub/switch port is normally MDI-X — this is why old-school networking needed special "crossover" cables to connect two switches together (matching TX-to-RX), while a "straight-through" cable connects an MDI device to an MDI-X device.
Auto MDI/MDI-XA feature that automatically senses and swaps which pins are transmit vs receive, so any cable (straight or crossover) works regardless of what's plugged into the other end. This chip supports it on every port, enabled by default.
Auto-negotiationThe handshake process where two linked Ethernet devices advertise their capabilities (10/100 Mbps, half/full duplex) to each other and automatically agree on the fastest mode both sides support.
Isolation transformer / magneticsA transformer placed between the PHY and the RJ45 jack that electrically isolates your board's ground from the cable — required by the Ethernet spec for safety and noise immunity, since a cable might run to a device with a different ground reference (even a different building).
MLT-3 encodingThe specific 3-level (not simple on/off) electrical signaling scheme used by 100BASE-TX to keep the signal's frequency spectrum narrower and reduce radiated EMI compared to simpler encodings.
LinkMD (cable diagnostics)A built-in feature using TDR (time-domain reflectometry — sending a pulse down the cable and timing its reflection) to detect and roughly locate cable faults like an open or short circuit, without any special test equipment.

Digital interfaces (how the switch talks to a CPU / other chips)

TermPlain-English meaning
MII (Media Independent Interface)A standardized parallel digital bus (4 data bits + control signals, clocked) between a MAC and a PHY. "Media independent" means the same interface works whether the physical media is copper, fiber, 10 Mbps, or 100 Mbps — the MAC doesn't need to know or care.
RMII (Reduced MII)A pin-count-reduced version of MII (2 data bits instead of 4, single shared clock) — same job, fewer wires, useful when you're pin-constrained on a CPU/FPGA.
SNI (Serial Network Interface)An even simpler, single-bit-wide legacy interface for connecting to older network-layer processing chips.
SPISerial Peripheral Interface — a common 4-wire synchronous serial bus (clock, data in, data out, chip-select) used here for a host CPU to read/write the switch's internal configuration registers.
I²CA 2-wire synchronous serial bus (clock + bidirectional data). Here the chip acts as an I²C master specifically to read its configuration from an external EEPROM at boot — not for a host CPU to control it live (that's what SPI/MDIO are for).
MDC / MDIO (MIIM)"Management Data Clock / Management Data I/O" — a simple 2-wire bus standardized for reading and writing PHY registers (things like link status, speed, duplex). Widely supported by external MAC chips as the conventional way to monitor an external PHY.
SMI (Serial Management Interface)A superset of MDC/MDIO used here to access all the switch's registers (not just PHY registers), for hosts that only have an MDIO-style bus available rather than SPI.
Strap pin / pin strappingA pin that is read once at reset to decide a configuration option (based on whether it's pulled high or low by an external resistor), and then afterward switches to its "normal" function (often an LED driver). It's how you configure a chip that has no CPU talking to it.

Switching / networking features

TermPlain-English meaning
VLAN (Virtual LAN)A way to logically split one physical switch into multiple isolated virtual networks — devices in different VLANs can't see each other's traffic even though they're plugged into the same physical switch, as if they were on separate physical switches.
802.1Q tagThe specific IEEE standard for how a VLAN ID gets embedded into an Ethernet frame's header, so switches along the path know which VLAN a frame belongs to.
QoS (Quality of Service)Mechanisms for treating some traffic as higher priority than other traffic — e.g. making sure a VoIP phone call's packets get sent before a large file transfer's packets, so the call doesn't stutter.
802.1p priorityA 3-bit priority field that can ride inside the 802.1Q VLAN tag, letting devices mark frames with a priority level (0–7) that switches use for QoS queuing decisions.
DiffServ / DSCPA Layer-3 (IP header) based alternative way of marking packet priority, using bits in the IP header's "Type of Service" field — this switch can classify QoS priority based on either the Layer-2 (802.1p) or Layer-3 (DSCP) marking.
Rate limitingCapping how much bandwidth a given port (or priority queue) is allowed to use, to prevent one busy device from starving the rest of the network.
Broadcast storm protectionA safety limit on how many broadcast (sent-to-everyone) packets per second are allowed through, since broadcast traffic gets copied out every port and a runaway flood can consume all switch bandwidth.
IGMP snoopingThe switch "listens in" on IGMP (Internet Group Management Protocol) messages — used for IP multicast (one sender, many specific receivers, e.g. IPTV) — so it only forwards multicast traffic out the ports that actually have a subscribed receiver, instead of blasting it out every port like a broadcast.
Port mirroringA diagnostic feature that copies all traffic seen on one port out to another port too, so you can plug a packet-capture tool into the mirror port and see everything happening on the network without interrupting it.
Spanning Tree Protocol (STP) / Rapid STP (RSTP)A protocol that prevents network loops (which would otherwise cause traffic to circulate forever and melt down the network) when switches are cabled together in a way that creates redundant paths — it automatically finds and "blocks" the redundant paths while keeping a backup ready if the main path fails. RSTP is a faster-converging revision of the original STP standard.
MIB counters (Management Information Base)Standardized statistics counters (packets sent/received, errors, collisions, etc.) per port, readable by a host CPU for monitoring and diagnostics — the same kind of counters your router's admin page uses to show "bytes sent/received."
Flow control (802.3x / PAUSE frames)A mechanism where a receiver that's getting overwhelmed sends a special "PAUSE" frame asking the sender to briefly stop transmitting, preventing buffer overflow and dropped packets.

Power / electrical terms

TermPlain-English meaning
LDO (Low-Dropout regulator)A type of linear voltage regulator that can output a voltage very close to its input voltage (small "dropout"). Simpler and quieter (less electrical noise) than a switching regulator, but less power-efficient for large voltage drops.
Decoupling capacitorA small capacitor placed right next to a chip's power pin to locally supply sudden bursts of current the chip needs (as its internal transistors switch) faster than the main power supply/traces could respond, and to shunt high-frequency noise to ground.
Ferrite beadA passive component that looks like a resistor but behaves like it has very low resistance at DC/low frequency and rising resistance at high frequency — used to block high-frequency noise from traveling between two parts of a circuit (e.g. digital noise leaking into an analog supply) while still passing DC power through cleanly.
Reset (RST_N, active-low)A signal that forces the chip into a known, defined starting state. "Active-low" (the "_N" suffix, or sometimes a bar over the name) means the reset is asserted when the pin is held low, and the chip runs normally when it's high.
Pull-up / pull-down resistorA resistor connecting a pin to power (pull-up) or ground (pull-down) so the pin has a defined logic level when nothing else is actively driving it — used both for strap-pin configuration and for open-drain buses like I²C/MDIO that need something to pull the line back high.

Package / part-numbering terms

TermPlain-English meaning
LQFP (Low-profile Quad Flat Package)A common surface-mount IC package shape — a thin square body with pins ("legs") along all four edges. This chip is a 128-pin LQFP.
-ND suffix (e.g. "KSZ8895MLUB-ND")Not part of the actual chip's part number — this is Digi-Key's own internal ordering/stock-keeping suffix, tacked onto the manufacturer part number for their catalog. The real chip is simply the KSZ8895ML (or "MLU"/"MLUB" depending on silicon revision/temperature grade).
Silicon revision (e.g. "B2 silicon")Chip manufacturers periodically revise the internal design ("silicon") of a part to fix bugs or add small features while keeping the same external part number and pinout. The "B2" revision of this chip, for example, added the LinkMD feature and improved ESD rating — worth checking which revision your specific part is if a datasheet feature seems missing in practice.

5. How it all fits together: a packet's journey

  1. An Ethernet cable carries an analog electrical signal into, say, Port 2's RJ45 jack, through the isolation transformer, into PHY 2.
  2. PHY 2 does the analog-to-digital heavy lifting (equalization, clock recovery, decoding the MLT-3/Manchester signal) and hands clean digital bits to MAC 2.
  3. MAC 2 checks the frame for errors, strips off the low-level framing, and passes the payload into the shared switch fabric / frame buffer.
  4. The lookup engine reads the destination MAC address and checks its internal address table: "which port has this happened to be plugged into before?" If found, it forwards only to that port. If not, it floods out every port except the one it came in on (and learns the answer once a reply comes back).
  5. Along the way, any configured VLAN, QoS, rate limiting, or port mirroring rules are applied.
  6. The frame is handed to the destination port's MAC, which re-frames it, and that port's PHY converts it back into an analog signal for the outgoing cable.
  7. Separately and asynchronously, if a host CPU is present, it can be reading MIB counters, adjusting registers over SPI/MDIO, or reacting to a link-change interrupt — none of this is in the way of the actual packet forwarding described above.
